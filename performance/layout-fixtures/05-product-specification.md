## 2. Release criteria

The following user journeys must remain coherent across every destination.

### Request journey

1. Open a request.
2. Record the promise.
3. Set a reminder.
4. Review the reply.
5. Confirm resolution.

### Invoice journey

1. Open the invoice.
2. Record payment.
3. Review a correction.

### Booking journey

1. Open the booking.
2. Review a reschedule.
3. Confirm cancellation.

## 4. Independent principles

1. Request → promise → reminder → reply → resolution.
2. Invoice → payment → correction.
3. Booking → reschedule → cancellation.

### Six qualities

1. **Clarity:** Find the main idea.
2. **Continuity:** Keep the reader's place.
3. **Balance:** Give ideas similar weight.
4. **Restraint:** Decorate with purpose.
5. **Fidelity:** Preserve the structure.
6. **Comfort:** Leave room to think.

## 5. Complex content remains vertical

### Evidence model

This section is deliberately much longer than a feature card. An observation is not
the same as a durable object, and uncertainty must remain visible to the reader.
Its explanation needs the full reading measure. Similar heading levels alone are
not enough to justify rearranging neighboring chapters into a grid. This text also
provides enough content to verify momentum scrolling, outer-edge scrollbar placement,
quote padding, and stable chapter numbering in a native window.

### Ownership model

1. Source authority
   - Preserve the original evidence.
   - Retain the ownership boundary.
2. User corrections
   - Store the reason and provenance.
